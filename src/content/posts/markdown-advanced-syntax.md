掌握了标题、列表和链接之后，你会发现标准 Markdown 在某些场景下不够用——比如需要脚注、任务清单或自定义文字颜色。好消息是，绝大多数现代解析器都支持一系列扩展语法，并且允许直接嵌入 HTML 来弥补不足。这篇文章把这些进阶技巧整理在一起，帮你把 Markdown 的表现力再推一个台阶。

## 表格

虽然原始 Markdown 规范不包含表格，但 GitHub、Typora、VS Code 等主流平台都已支持通过竖线 `|` 创建表格：

```markdown
| 左对齐 | 居中对齐 | 右对齐 |
| :--- | :---: | ---: |
| 内容A | 内容B | 内容C |
| 左边 | 居中 | 右边 |
```

冒号 `:` 的位置决定对齐方式：左侧为左对齐，两侧都有为居中，右侧为右对齐。表头分隔行（第二行的 `---`）是必不可少的，缺少它表格不会被识别。

## 脚注

脚注常用于学术文档或技术博客中的补充说明，渲染后通常显示在页面底部：

```markdown
这是一个带有脚注的句子[^1]。

[^1]: 这是脚注的具体内容。
```

`[^标识符]` 是引用标记，标识符可以是数字或字母。脚注的定义可以放在文档任意位置，但习惯上集中在文末。需要注意的是，GitHub 从 2023 年起才原生支持脚注语法，较早版本可能不识别。

## 任务列表

在 GitHub 的 README 或 Issue 中经常见到的勾选框，语法非常简洁：

```markdown
- [x] 完成项目规划
- [ ] 编写代码
- [ ] 提交测试
```

`[x]` 表示已完成（不区分大小写），`[ ]` 表示未完成。这个语法在项目管理文档中特别实用，可以直接在仓库里追踪进度。

## 定义列表

用于解释术语或词汇，格式是术语独占一行，下一行以冒号 `:` 开头：

```markdown
苹果
: 一种水果。
: 也是一家科技公司。
```

不是所有解析器都支持定义列表——GitHub 不支持，但 Typora 和很多静态博客生成器（如 Jekyll、Hugo）支持。使用前建议先确认目标平台的兼容性。

## 上下标

在数学公式或化学式中常用：

- **上标**：`^` 符号，如 `m^2` 显示为 m²
- **下标**：`~` 符号，如 `H~2~O` 显示为 H₂O

这两个语法同样不是所有平台都支持。如果需要更好的兼容性，可以用 HTML 标签 `<sup>` 和 `<sub>` 替代。

## 注释

如果想在源码中留下笔记但不希望在渲染结果中显示，可以使用 HTML 注释：

```html
<!-- 这是一段注释，用户看不见 -->
```

这在协作写作或记录待办事项时很方便。

## 混合 HTML 与 CSS

标准 Markdown 不支持颜色、字体大小或背景高亮，但你可以直接在 `.md` 文件中嵌入 HTML 和内联 CSS：

### 文字颜色与字体

```html
<font color='red' face='宋体' size='4'>这段文字是红色的宋体。</font>
```

### 背景高亮

虽然部分编辑器支持 `==高亮==` 语法，但更通用的做法是用 HTML：

```html
我是<span style="background-color: #ff0; color: #000">高亮的文字</span>。
```

### 折叠内容

这在技术文档中非常有用，可以把复杂代码或长篇解释隐藏起来，点击才展开：

```html
<details>
<summary>点击这里展开/收起内容</summary>
这里是被隐藏的详细内容。
</details>
```

GitHub 对 `<details>` 标签的支持非常好，适合在 README 中组织 FAQ 或可选的配置说明。

> **提示**：HTML 混排的兼容性因平台而异。GitHub 会过滤大部分内联样式（如 `style` 属性），但保留 `<details>`、`<sup>` 等语义化标签。个人博客（Jekyll/Hugo）通常不做过滤，可以自由使用。

## 小结

- 表格、任务列表、脚注在主流平台通用性很高，可以放心使用。
- 定义列表和上下标的兼容性较差，使用前需确认目标平台。
- HTML 混排是突破 Markdown 表现力上限的关键手段，但要注意平台过滤策略。
- 折叠内容（`<details>`）是组织长文档的利器，尤其适合技术文档和 README。
- 进阶语法的选择原则：优先用标准扩展语法，实在不行再上 HTML。
