踩坑笔记：环境、现象、排查、结论、待办，分开记录已解决和未解决的问题。所有条目都不包含账号、密码或令牌。

已解决

火山引擎 ve CLI 安装失败 已解决

环境：Windows 10/11，Node 24，npm 11，安装 @volcengine/cli 时触发解压脚本。

现象：安装报错 Expand-Archive : The 'Expand-Archive' command was found in the module 'Microsoft.PowerShell.Archive', but the module could not be loaded，CLI 二进制解压失败，包整体回滚。

排查：列出 PSModulePath 后发现，Codex 运行环境自带的 PowerShell 模块目录里有一份 Microsoft.PowerShell.Archive 1.2.5，位置排在系统模块目录之前；Windows PowerShell 自动加载时选中了这份与 5.1 不兼容的版本，加载失败后没有继续回退到系统目录里的版本。

解法：安装前把 PSModulePath 指向系统模块目录（C:\Program Files\WindowsPowerShell\Modules;C:\WINDOWS\system32\WindowsPowerShell\v1.0\Modules），再执行安装，一次成功，随后技能也正常装上。

结论：本质是模块搜索路径的遮蔽问题，不是网络或权限问题。

GitHub 推送连接被重置 已解决

现象：git push 到 github.com 时，TCP 握手和 TLS 都能建立，但请求发出后约 25 秒被对端重置，报 Recv failure: Connection was reset；网页版和 API 当时也时好时坏。

排查：换多个 GitHub 出口 IP、强制 HTTP/1.1、调大 postBuffer 都不行，判断是链路层被掐断，而不是仓库或令牌问题。

当时的方案：改用 GitHub 的 SSH 443 通道（ssh.github.com:443），配一把专用 SSH 密钥，推送恢复。

补充：后来确认当时只是本地代理没开；代理开启后直连、网页和 API 都恢复正常。SSH 443 作为备用通道保留。

未解决 / 待处理

arkcli 的 update_execution_boundary 拦截 未解决

环境：在 Codex 桌面应用内运行 @volcengine/ark-cli。

现象：任意业务命令（包括 doctor）执行前自检失败，返回 update_execution_boundary：Windows 文件句柄解析到应用私有目录里的硬链接文件，而不是 npm 全局目录，命令被拦下。

已尝试：直接调用 exe、关闭自动更新（update.mode=disabled）、核对硬链接与路径，均未绕开；判断与应用对用户目录的虚拟化有关。

待办：找官方对「非规范安装路径」的放行方式，或等新版本修复后重试。

ve 技能需要火山引擎 AK/SK 未解决

现状：ve 命令行和技能已装好，但初始化身份检查返回「未配置登录凭证」。

原因：方舟的 ARK API Key 与 ve 需要的火山主账号 AccessKey / SecretKey 不是同一套凭证，不能通用；ve 支持 AK/SK 配置、浏览器扫码登录和 SSO 三种方式。

待办：提供 AK/SK，或走一次浏览器登录后即可继续。

校园网自动登录接口待实测 待验证

现状：校园网登录工具按学校公开指南（认证网关、触发地址）和常见的 Dr.COM 认证方式实现，但编写环境不在校园网内，无法实网验证接口字段。

兜底：无论自动登录是否成功，工具都会保证把认证页弹出来，不影响手动登录。

待办：在校园环境实测一次；若自动登录失败，把图形界面日志里卡住的那行发回来，再按真实页面结构调整。
